Installation and daily use

Dev Harness tutorial

Configure the global palette, repositories, worktrees, AI commands, and Obsidian.

v0.3.0 preview macOS + Windows Git Bash 11 sections

01

Install the four requirements

Dev Harness requires:

  • Bash — system Bash on macOS or Git Bash on Windows
  • Task
  • Git
  • fzf

Useful optional integrations include rg, VS Code, Atuin, Docker, Obsidian, and the AI CLI of your choice.

fzf: used by the command palette and interactive selectors. Every Task command can also be called directly.

02

Run the Docker demo

From a release archive or source checkout, build the demo image:

build locally 
docker build -f demo/Dockerfile -t dev-harness-demo .
start interactive demo 
docker run --rm -it dev-harness-demo

The container starts in a payments-demo repository with a baseline commit, a modified Java file, and a new note. Try gtask, gtask open, gtask changed, gtask search -- retry, and gtask context.

No host folders or credentials are mounted. Files open in terminal less—press q to return. VS Code, Obsidian, Docker-in-Docker, and external AI CLIs are not connected.

03

Run the local installer

Download and extract a release archive or use a source checkout, then run the local installer:

macOS / Git Bash 
./install.sh --configure-shell
Windows PowerShell 
powershell -ExecutionPolicy Bypass \
  -File .\install.ps1 --configure-shell

Restart the terminal or reload Bash:

source ~/.bashrc

Updates preserve personal configuration. Uninstall removes only files recorded in the installation manifest.

04

Point Dev Harness at your workplace

DEV_WORKPLACE is the directory containing your project folders:

~/Workplace/
├── payments/
├── orders/
└── notifications/

Edit ~/.config/dev-harness/config.env:

export DEV_WORKPLACE="$HOME/Workplace"
export DEV_EDITOR="code"

export DEV_OBSIDIAN_VAULT=""
export DEV_OBSIDIAN_VAULT_PATH="$HOME/Documents/Obsidian/My Vault"

export DEV_AI_COMMAND="codex"
export DEV_AI_REVIEW_COMMAND="codex exec -"
export DEV_AI_RESUME_COMMAND="codex exec -"

export DEV_CONTEXT_MAX_LINES="4000"
export DEV_RESUME_LIMIT="10"
export DEV_TODO_DEFAULT_PRIORITY="p2"

An empty vault setting uses the active Obsidian vault. Replace the AI command values with Codex, Claude, Gemini, Copilot CLI, OpenCode, or another command that accepts the same input.

validate 
gtask doctor

05

Find a project or file

Open the global palette:

gtask

Search by task name, English description, or hidden Polish keywords such as projekt, plik, notatka, and zadanie.

cprojselect a project and change directory
oprojselect a project and open it in DEV_EDITOR
cworkchange directory to DEV_WORKPLACE
cvaultchange directory to DEV_OBSIDIAN_VAULT_PATH
resumereturn to a recent project or worktree
grreturn to the current Git worktree root
dirtyselect unfinished work and change directory
whyexplain the current repository context
gtask openselect a file below the current directory, with or without Git
gtask changedselect a changed file, even before the first commit
gtask search -- OrderServicesearch repository content

The resume preview shows branch state, changes relative to the base, and the highest-priority project TODO. It uses Atuin history when available and shell history otherwise.

Orient and hand off

dirty
why
focus p0
handoff --copy
standup --day

Enter in dirty or focus changes the current shell directory; their gtask variants print the selected path. Ctrl-O opens the worktree or TODO note without changing directory. Project resolution for focus fails closed when no unique repository matches.

These commands are read-only unless an option says otherwise. handoff --copy and standup --copy use the clipboard. standup --day appends to today's Daily note. They do not invoke AI. Review commit subjects and TODO titles before sharing the output.

06

Create a worktree

cd "$DEV_WORKPLACE/payments"
gtask wt -- feature/retry-policy
cwt

The generated path contains a timestamp. If the same name already exists, Dev Harness adds a numeric suffix instead of overwriting it.

Use the project's own commands for project-specific work:

task test
task build
task run

These are examples of project-local commands. Dev Harness does not define global build, test, run, deploy, or release tasks.

Select AI context

gtask changes
gtask context
gtask review

gtask review requires an interactive terminal and explicit fzf selection. Without interaction it fails closed and does not invoke AI.

All changed files

gtask review -- --all

This sends every changed path that survives the sensitive-path policy. Review the repository state first.

The filter excludes common environment files, private keys, keystores, .ssh, and complete credentials*/secrets* trees. Inspect the selected paths before sending them to an external service.

07

Write notes

Enable the Obsidian command-line interface. On Windows, Dev Harness uses the official Obsidian.com redirector when available.

gtask note -- "Retry design"create a normal note under Notes/
gtask day -- "Fixed payment timeout"append today's progress under Daily/
gtask week -- "Migration completed"append a weekly summary under Weekly/

Configure Obsidian's Daily notes core plugin to use Daily/. Dev Harness follows that native setting rather than creating a second daily-note convention.

Tag rule: use tags for themes such as java, security, or architecture. Keep project, status, priority, and dates as Obsidian properties.

08

Track TODOs

Each TODO is a standalone Markdown file under TODO/<year>/<month>/. Creation runs inside a Git repository so the repository root name becomes the project property.

gtask todo -- "Check retry policy"          # P2 default
gtask todo -- p0 "Fix data leak"
gtask todo -- p1 "Check retry metrics"
gtask todo -- p3 "Clean up test names"
P0 critical P1 high P2 medium P3 low 
gtask todo              # open TODOs for this project
gtask todo -- p1        # project P1 items
gtask todos             # open TODOs across the vault
gtask todos -- done     # completed items
gtask done              # select and complete
gtask reopen            # select and reopen

Completion only updates status and completed. The path stays stable, so links in Obsidian do not break.

# Find and orient
dirty
why
focus p1

# Do
gtask wt -- feature/retry-policy
cwt

gtask changes
gtask review

# Remember

gtask todo -- p1 "Check retry metrics in test environment"

# Tomorrow
dirty
Find→Do→Remember→resume

10

Extend the global palette

Add general-purpose personal tasks to ~/.config/dev-harness/Taskfile.yml. Never edit managed files under ~/.dev-harness.

version: '3'

tasks:
  ports:
    desc: Show listening ports
    dir: '{{.USER_WORKING_DIR}}'
    cmds:
      - your-command-here

Run it with gtask ports. To make it searchable, add a tab-separated row to ~/.config/dev-harness/palette.tsv:

ports<TAB>show listening ports<TAB>network porty sockets

Use gtask extend for the built-in guide. Keep project-specific workflows in each project's local Taskfile.

11

Diagnose, update, or remove

gtask doctorvalidate the supported installation
gtask helpshow the workflow cheat sheet
gtask aliasesshow shell and Task fast paths
./install.sh updaterefresh managed files
./install.sh --dry-runpreview installation without writes
./install.sh uninstallremove only managed files

uninstall --purge-config additionally removes known Dev Harness configuration files, but still preserves unknown files, notes, and the Obsidian vault.
